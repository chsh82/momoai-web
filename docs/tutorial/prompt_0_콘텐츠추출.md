# 튜토리얼 개발 0단계 — 콘텐츠를 JSON으로 추출

너는 momoai.kr(Flask 3.1 / SQLAlchemy 2.0 / SQLite / Jinja2+Tailwind / Alpine.js) 리포에서 작업한다.
이번 단계는 **화면을 만들지 않는다.** 교재 빌더 스크립트에 흩어져 있는 글쓰기 튜토리얼 콘텐츠를,
앞으로 튜토리얼과 교재가 함께 읽을 **버전 관리되는 JSON 파일**로 옮기는 것이 전부다.

## 배경

- 이미 만들어진 교재 《문장과 생각》 초등판의 1부(원고지 14규정)가
  `build_elem.py`의 `RULES` 리스트에 파이썬 dict로 들어 있다. (같은 폴더 `docs/tutorial/build_elem.py`)
  - 이 파일은 맨 위에서 `from gp import grid, ex` 를 한다. `gp.py`가 없으면 임포트가 실패한다.
    **`gp.py`를 찾아 오지 말고**, 추출용으로 `grid`/`ex`를 빈 함수로 스텁한 임시 모듈을 만들어 `RULES`만 읽어라.
    (또는 `ast`로 `RULES` 리터럴만 파싱해도 된다. 어느 쪽이든 임시 파일은 커밋하지 않는다)
  - 임포트하면 모듈 맨 아래에서 교재 HTML을 파일로 쓴다. 이 산출물은 무시하고 커밋하지 않는다.
- 원고지 그림은 HTML을 직접 쓰지 않고 **문자열 한 줄 = 원고지 한 줄** 표기법으로 쓴다.
  - `(공백)` 빈 칸 · `{20}` 한 칸에 여러 글자 · `!x` 강조 칸 · `#x` 강조+부호를 칸 가운데에 잘못 놓음 · `~x` 두 줄 긋기
  - 예: `'해법은 다르!{다.}'` → 일곱 칸, 마지막 칸에 '다.'가 함께 들어가고 강조.
  - `!`와 `#`는 **다르게 렌더된다.** `!.`는 마침표가 칸 왼쪽 아래(정상 위치)에 찍히고,
    `#.`는 칸 가운데에 크게 찍힌다(잘못된 모습). 오답 예시에서 이 둘을 바꿔 쓰면 **오답 그림이 정답처럼 보인다.**
    원문의 `!`/`#`를 절대 서로 바꾸지 마라.
- 이 표기법은 건드리지 말고 문자열 그대로 JSON에 옮긴다. (렌더러가 이 문자열을 파싱한다)

## 산출물

`app/tutorial/content/elem/course1.json` 한 파일. 스키마는 아래를 **정확히** 따른다.

```json
{
  "track": "elem",
  "course": "course1",
  "title": "원고지 — 칸의 약속",
  "lede": "원고지는 어려운 규칙이 아니라 칸을 쓰는 약속이에요...",
  "lessons": [
    {
      "id": "elem-c1-l1",
      "order": 1,
      "title": "원고지 편 · 레슨 1",
      "cards": [
        {
          "no": "2",
          "star": true,
          "title": "문단이 시작되면 첫 칸을 비워요",
          "say": "새 문단을 시작할 때는 <b>첫 칸을 비우고 둘째 칸부터</b> 써요...",
          "why": "첫 칸이 비어 있으면 읽는 사람이 ...",
          "remember": "다 쓰고 나서 왼쪽 첫 칸만 훑어보세요...",
          "grids": [
            { "tone": "bad",  "n": 13, "tag": "첫 칸부터 글자를 썼어요",   "rows": ["!첫 칸부터 썼어요."] },
            { "tone": "good", "n": 13, "tag": "첫 칸을 비우고 시작했어요", "rows": ["!{ }첫 칸을 비웠어요."] }
          ],
          "category": "관행"
        }
      ],
      "questions": [
        {
          "id": "elem-c1-l1-q1",
          "type": "choice",
          "ruleNo": "2",
          "ruleName": "문단 첫 칸",
          "q": "문단을 시작하는 바른 모습은?",
          "opts": [
            { "n": 13, "rows": ["!첫 칸부터 썼어요."] },
            { "n": 13, "rows": ["!{ }첫 칸을 비웠어요."] }
          ],
          "a": 1,
          "why": "문단이 바뀔 때마다 <b>첫 칸을 비우고 둘째 칸부터</b> 써요."
        }
      ]
    }
  ]
}
```

### 필드 규칙

- `cards[]`는 `build_elem.py`의 `RULES` 필드를 그대로 매핑한다:
  `no→no`, `star→star(없으면 false)`, `title→title`, `say→say`, `why→why`,
  `try_→remember`, `note→note`,
  그리고 `bad/bad_cap/good/good_cap/n`을 `grids` 배열로 합친다
  (bad는 `{tone:"bad", n, tag:bad_cap, rows:bad}`, good은 `{tone:"good", ...}`).
- **원문에 없는 필드는 만들지 않는다.** `try_`는 일부 규정에만 있다(1·2번뿐). 없으면 `remember` 키 자체를 넣지 마라.
  다른 규정의 문구를 가져오거나 새로 쓰지 마라. `note`도 마찬가지(7·14번만 있다).
- `bad`가 없는 규정(7·8·14번)은 `grids`에 good 하나만 넣는다. 빈 bad를 만들지 마라.
- `n`이 없는 규정(1번)은 `grids`의 `n`을 `null`로 둔다. 렌더러가 행 길이에서 자동 계산한다. 임의의 숫자를 넣지 마라.
- `category`는 규정/어법/권장/관행 중 하나. 원고지 편은 **전부 `"관행"`**으로 넣는다.
  (교재 제작 기록의 결정사항. 나중에 채점 지표 연동 시 규정·어법만 반영하기 때문에 필요하다.
  `grids[].tag`는 그림 캡션이라 이름이 다르다 — 둘을 섞지 마라)
- 문항 배열의 키 이름은 **`questions`** 다. (참고 샘플 HTML의 `LESSON` 상수는 `quiz`라는 이름을 쓰지만,
  JSON은 `questions`로 통일한다. 1단계에서 JS 쪽을 맞춘다)
- `questions[]`는 교재에 없다. **새로 만들지 말고**, 이번 단계에서는 아래 레슨 구성만 채운다(문항은 내가 준 것만 넣는다).

### 참고 샘플 HTML을 문구 출처로 쓰지 말 것

화면설계 샘플(`모모아이_글쓰기튜토리얼_초등샘플.html`)에도 같은 규정이 들어 있지만,
그 안의 문구는 **손으로 윤색된 것**이다(예: 5·10번 `why`에 `<em>` 강조가 덧붙어 있고,
10번에는 `RULES`에 없는 `remember`가 지어져 있다).
샘플은 **화면 구조와 CSS의 출처일 뿐**이고, 콘텐츠 원문은 언제나 `build_elem.py`의 `RULES`다.
충돌하면 `RULES`를 따른다.

### 이번에 담을 레슨 (레슨 1 하나만)

레슨 1에 넣을 규정 카드 4개와 문항 4개는 아래를 그대로 쓴다. (규정 원문은 `RULES`에서 no로 찾아 옮긴다)

- 카드: no `2`(★), `5`(★), `6`, `10`(★)  ← 이 순서
- 문항 4개(`id`는 아래 그대로 넣는다. 1단계에서 정답 기록의 키로 쓴다):
  1. `id:"elem-c1-l1-q1"` · `type:choice` · ruleNo `2` · "문단을 시작하는 바른 모습은?" · opts `[{n:13,rows:["!첫 칸부터 썼어요."]},{n:13,rows:["!{ }첫 칸을 비웠어요."]}]` · a `1`
  2. `id:"elem-c1-l1-q2"` · `type:choice` · ruleNo `5` · "앞 줄이 꽉 찼고 다음 낱말로 넘어가요. 바른 모습은?" · opts `[{n:6,rows:["환경 문제는","!{ }심각해요."]},{n:6,rows:["환경 문제는","심각해요."]}]` · a `1`
  3. `id:"elem-c1-l1-q3"` · `type:fill` · ruleNo `6` · "'2026년'을 원고지에 놓아 보세요." · `n:6` · `answer:["20","26","년","","",""]` · `pieces:["20","26","2","0","년"]`
  4. `id:"elem-c1-l1-q4"` · `type:choice` · ruleNo `10` · "줄이 꽉 찼는데 마침표를 찍어야 해요. 바른 모습은?" · opts `[{n:7,rows:["해법은 달라요","#."]},{n:7,rows:["해법은 달라!{요.}"]}]` · a `1`
     - 오답 보기의 `#.`는 오타가 아니다. 규정 10번의 `bad` 원문과 같은 표기이며, 마침표가 칸 가운데에 잘못 놓인 모습을 보여준다.
  - 각 문항의 `why`, `ruleName`은 해당 규정 카드의 내용으로 자연스럽게 채운다.

## 검증

- `python -c "import json; d=json.load(open('app/tutorial/content/elem/course1.json',encoding='utf-8')); print(len(d['lessons'][0]['cards']), len(d['lessons'][0]['questions']))"` → `4 4`
- 카드 4장의 `say`/`why`가 `RULES` 원문과 **문자 단위로 같은지** 대조한다(윤색·축약·태그 추가 금지).
- 카드 `2`만 `remember`를 가지고, `5`·`6`·`10`에는 `remember` 키가 **없는지** 확인한다.
- 모든 원고지 `rows` 문자열이 표기법을 그대로 보존하는지(특히 `{ }`, `!`, `#`) 눈으로 확인한다.
  문항 4의 오답 보기가 `#.`인지 다시 본다.
- JSON은 `ensure_ascii=false`로 한글이 그대로 보이게 저장한다.

## 하지 말 것

- 화면·라우트·모델·CSS를 만들지 마라. 이 단계는 JSON 파일 하나만 만든다.
- 규정 문구를 고치지 마라. `RULES` 원문 그대로 옮긴다.
- 중등판/코스2/코스3은 건드리지 마라. 다음 단계에서 한다.
- 레슨 2·3(나머지 10규정)은 이번에 넣지 마라. 단, 위 필드 규칙(`note`, bad 없음, `n` 없음)은
  그때 쓸 규정들 때문에 미리 정해 둔 것이니 로직에서 빠뜨리지 마라.
