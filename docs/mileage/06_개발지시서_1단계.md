## 작업 범위

### 1. 모델 정의 — `app/models/mileage.py`

설계서 2절의 5개 테이블을 SQLAlchemy 모델로 정의한다.

- `PointEvent`, `Badge`, `StudentBadge`, `MonthlyRanking`, `MileageConsent`
- FK 컬럼 타입은 참조 대상 테이블의 PK 타입과 **정확히 일치**시킬 것 (직접 확인 후 결정)
- `UniqueConstraint`와 인덱스를 설계서대로 반드시 포함할 것
- 기존 모델의 작성 스타일(한글 docstring, `datetime.utcnow` default, `__repr__`)을 따를 것
- `app/models/__init__.py`의 `__all__`에 새 모델을 등록할 것

### 2. 기존 모델 변경

`app/models/community.py`의 `Comment`에 소프트 삭제 컬럼 2개를 추가한다.
- `is_deleted` Boolean, default False, nullable False
- `deleted_at` DateTime, nullable True

**기존 댓글 조회 쿼리는 이번 단계에서 수정하지 않는다.** 컬럼만 추가하고, 조회 필터 적용은 2단계에서 한다.

### 3. 규칙 상수 — `app/services/mileage_rules.py`

정책 문서 제4조의 적립표를 딕셔너리 상수로 정의한다.

```python
POINT_RULES = {
    'RW01': {
        'name': '리라이팅 제출',
        'points': 500,
        'source_type': 'essay',
        'confirm_delay_hours': 0,   # 0이면 즉시 확정
        'daily_cap': None,          # 건수 상한
        'monthly_cap': None,        # 점수 상한
    },
    ...
}
```

- 정책 문서의 9개 코드(RW01, EX01, QZ01, QZ02, QS01, QS02, CM01, AT01, AT02, EV01)를 빠짐없이 정의할 것
- 상한 값은 정책 문서와 한 글자도 다르지 않게 옮길 것
- 값을 임의로 판단해 바꾸지 말 것. 문서에 없는 값이 필요하면 작업을 멈추고 질문할 것

### 5. 마이그레이션

- `flask db migrate -m "add mileage tables"` 로 alembic 마이그레이션 파일을 생성한다
- 생성된 파일을 **반드시 열어서 확인**하고, 의도하지 않은 기존 테이블 변경이 포함되어 있으면 그 부분을 삭제한다
- 로컬에서 `flask db upgrade` 로 적용해 오류가 없는지 확인한다
- 루트의 애드혹 `migrate_*.py` 스크립트 방식은 사용하지 않는다

### 6. 뱃지 초기 데이터

`badges` 테이블에 BG01~BG10 10개 행을 넣는 스크립트를 `scripts/seed_badges.py`로 작성한다. 이름·설명·카테고리·반복 여부는 정책 문서 8.1을 그대로 따른다. 여러 번 실행해도 중복되지 않도록 이미 있으면 건너뛴다.

### 7. 확인 스크립트

`test_mileage_service.py`를 루트에 작성한다. 이 프로젝트의 기존 `test_*.py` 관행대로 pytest가 아니라 `create_app()`으로 앱 컨텍스트를 만들고 `print()`로 결과를 확인하는 스크립트로 만든다.

확인할 항목
1. 학생 1명에게 RW01 적립 → 500점 조회되는가
2. 같은 essay_id로 다시 적립 시도 → None 반환, 점수 그대로인가
3. CM01을 하루 6번 적립 시도 → 5건만 들어가는가
4. 적립 취소 → 합계가 0이 되고, 원장에는 2줄(적립·취소)이 남는가
5. 등급 계산이 정책표와 일치하는가 (0 / 5,000 / 20,000 / 50,000 / 100,000 경계값)

**스크립트는 테스트용으로 만든 데이터를 마지막에 반드시 롤백하거나 삭제할 것.**
