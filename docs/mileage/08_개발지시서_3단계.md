# 개발 지시서 3단계 — 배치 작업과 뱃지 엔진

## 사용 방법

2단계 확인이 끝난 뒤 시작한다. 이 단계는 **정기 실행되는 작업**을 다루므로, 로컬에서 함수를 직접 호출해 결과를 확인한 뒤 스케줄러에 등록한다.

--- 프롬프트 시작 ---

마일리지 기능 3단계를 구현한다. 정기 배치 작업 4종과 뱃지 판정 엔진을 만든다. 화면은 만들지 않는다.

## 먼저 읽을 것

- `app/utils/scheduler.py` — 기존 job 3개의 작성 패턴과 fcntl 락 구조
- `app/models/notification.py` — `Notification.create_notification()`
- `app/models/attendance.py`, `app/models/course.py`, `app/models/session_adjustment.py` — 출결 판정에 필요
- `docs/mileage/01_마일리지_운영정책.md` 제7조·제8조

## 공통 원칙

1. 배치 함수는 `app/services/` 안에 두고, `app/utils/scheduler.py`에서는 **호출만** 한다. 스케줄러 파일에 로직을 넣지 않는다.
2. 기존 job과 동일하게 `with app.app_context(): try/except`로 감싸고, 예외는 로깅만 하고 삼킨다. 한 학생 처리 실패가 전체 배치를 중단시키면 안 된다.
3. **모든 배치는 여러 번 실행해도 결과가 같아야 한다.** 유니크 제약과 `source_id` 조합 키로 중복 지급을 막는다. 배치 실패 후 재실행은 흔한 일이다.
4. 학생 수가 늘어날 것을 감안해 전체를 한 번에 메모리에 올리지 말고 나눠서 처리한다.

## 작업 범위

### 1. 대기 포인트 확정 배치

`mileage_service.confirm_pending_points()`를 호출하는 job. **1시간 간격** 실행.

질문·댓글의 24시간 대기 포인트를 확정 상태로 바꾼다.

### 2. 주간 출석 집계 — AT01

**매주 월요일 00:10** 실행. 직전 주(월~일)를 대상으로 한다.

- 각 학생의 해당 주 `Attendance` 기록에서 출석 인정 건수를 센다
- 정책 기준인 "주 5일 이상"을 만족하면 AT01 100점 적립
- `source_id`는 `{student_id}-{연도}-W{ISO주차}` 형식
- 수업이 주 1회인 학생은 이 조건을 만족할 수 없다. **정책의 "주 5일" 기준이 실제 수업 주기와 맞는지 확인이 필요하므로, 기준 일수를 `mileage_rules.py`의 상수로 빼서 나중에 조정할 수 있게 한다.**

### 3. 분기 완주 판정 — AT02

**분기 종료 다음 날 00:20** 실행 (1/4/7/10월 1일).

- 직전 분기의 정규 수업 회차를 학생별로 조회
- 결석이 0건이면 1,000점 적립
- 결석했더라도 `SessionAdjustment`로 보강 이수가 확인되면 출석으로 인정
- 분기 도중 등록해 전 회차를 이수할 수 없는 학생은 대상에서 제외
- `source_id`는 `{student_id}-{연도}Q{분기}` 형식

판정 근거(총 회차, 결석 수, 보강 인정 수)를 로그에 남긴다. 학부모 문의가 들어왔을 때 확인할 수 있어야 한다.

### 4. 월간 랭킹 확정 — `app/services/ranking_service.py`

**매월 1일 00:30** 실행. 전월을 대상으로 한다.

```python
def build_ranking(season, finalize=False) -> list
    # 시즌 포인트를 학년(레벨) 그룹별로 집계해 순위 산정
    # finalize=True면 monthly_rankings에 저장하고 is_final=True

def get_ranking(season, level_group=None) -> list
    # 확정된 스냅샷 조회. 없으면 잠정 순위를 실시간 계산해 반환
```

- 집계 대상: `status='confirmed'` 이면서 해당 시즌인 `point_events`의 합계
- 그룹 기준: 학생의 학년 값. 저학년과 고학년이 같은 표에서 경쟁하지 않도록 한다
- 동점 처리: ① EX01 적립 건수 ② RW01 적립 건수 ③ 해당 점수 도달 시각 순
- 랭킹 공개에 동의하지 않은 학생(`mileage_consents`의 A항목 미동의 또는 철회)은 **순위 산정에는 포함하되 표시는 익명으로** 한다. 순위 자체에서 빼면 다른 학생의 등수가 왜곡된다
- 확정은 **매월 3일**에 이루어진다. 1일 배치는 집계만 하고 `is_final=False`로 저장, 3일 배치에서 `is_final=True`로 전환하는 방식으로 구현한다

### 5. 뱃지 엔진 — `app/services/badge_service.py`

```python
def evaluate_badges(student_id, trigger_codes=None) -> list
    # 해당 학생의 미획득 뱃지 조건을 검사해 충족분을 부여하고 부여 목록 반환

def grant_badge(student_id, badge_code, granted_by=None) -> StudentBadge | None
    # 수동 수여. 반복 가능 뱃지는 earned_count 증가

def revoke_badge(student_id, badge_code, reason) -> bool
```

`badges.rule_type`별 판정 방식

| rule_type | 판정 | 해당 뱃지 |
|---|---|---|
| first_event | 해당 활동 코드의 confirmed 적립이 1건 이상 | BG01, BG02, BG03, BG04, BG05, BG06 |
| external_metric | 받은 좋아요/댓글 수 집계 | BG07 |
| count_threshold | 분기 완주(AT02) 누적 건수 | BG08 |
| manual | 관리자 수여만 | BG09 |
| all_badges | 지정된 뱃지 전부 보유 | BG10 |

- BG07은 **본인 글에 본인이 누른 좋아요와 삭제된 게시물의 좋아요를 제외**하고 센다
- BG10은 다른 뱃지가 부여될 때마다 함께 검사한다
- 뱃지를 부여할 때 `Notification.create_notification()`을 호출한다. 인앱 알림과 웹푸시가 함께 나간다
- 학생과 연결된 학부모에게도 알림을 보낸다. `ParentStudent` 연결을 이용하는 기존 패턴(`app/essays/routes.py`)을 따른다

**호출 시점**: 매일 새벽 배치로 전체 학생을 검사하는 방식과, 포인트 적립 직후 해당 학생만 검사하는 방식 둘 다 구현한다. 평소에는 적립 직후 검사로 즉시 반응하고, 새벽 배치는 누락 보정용으로 둔다.

### 6. 스케줄러 등록

`app/utils/scheduler.py`에 job 4개를 추가한다. 기존 job의 등록 패턴과 fcntl 락 구조를 그대로 따른다.

| job | 주기 |
|---|---|
| mileage_confirm | 1시간 간격 |
| mileage_weekly | 매주 월요일 00:10 |
| mileage_quarterly | 1/4/7/10월 1일 00:20 |
| ranking_monthly | 매월 1일 00:30, 매월 3일 00:30 |
| badge_sweep | 매일 03:00 |

### 7. 수동 실행 스크립트

각 배치를 터미널에서 직접 실행할 수 있는 스크립트를 `scripts/run_mileage_batch.py`로 만든다. 인자로 배치 이름과 대상 기간을 받는다.

```
python scripts/run_mileage_batch.py weekly --week 2026-W36
python scripts/run_mileage_batch.py ranking --season 2026-08 --dry-run
```

`--dry-run` 옵션에서는 DB에 쓰지 않고 결과만 출력한다. 배치가 실패했을 때 재실행하거나, 운영 중 결과를 확인할 때 필요하다.

## 확인 방법

각 배치를 `--dry-run`으로 먼저 실행해 결과를 눈으로 확인한 뒤 실제 실행한다. 확인할 항목

1. 주간 배치를 두 번 실행해도 점수가 두 번 붙지 않는가
2. 분기 완주 판정이 결석·보강 데이터와 맞는가 (샘플 학생 3명을 손으로 검증)
3. 랭킹 동점자 처리가 정책 순서대로 되는가
4. 뱃지 부여 시 알림이 학생과 학부모 양쪽에 가는가

## 하지 말 것

- 화면·템플릿 작업 (4단계)
- 스케줄러 파일에 비즈니스 로직 작성
- 기존 job 3개의 동작 변경
- 배치 안에서 예외를 밖으로 던지기
