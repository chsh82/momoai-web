# 개발 지시서 2단계 — 활동별 적립 훅 연결

## 사용 방법

1단계가 정상 동작하는 것을 확인한 뒤에 시작한다. 프로젝트 폴더에서 `claude` 실행 후 아래 프롬프트를 붙여넣는다.

---

--- 프롬프트 시작 ---

마일리지 기능 2단계를 구현한다. 1단계에서 만든 `mileage_service.award_points()`를 **기존 활동 지점에 연결**한다. 화면은 만들지 않는다.

## 먼저 읽을 것

- `app/services/mileage_service.py`, `app/services/mileage_rules.py` — 1단계 결과물
- `docs/mileage/05_DB설계서.md` 3절 — 활동 코드와 데이터 매핑표
- `docs/mileage/01_마일리지_운영정책.md` 제4조·제5조

## 연결 원칙

1. **기존 로직을 바꾸지 않는다.** 적립 호출을 기존 흐름 끝에 덧붙이기만 한다.
2. **적립 실패가 기존 기능을 막지 않는다.** 모든 적립 호출을 `try/except`로 감싸고, 실패 시 로그만 남기고 진행한다. 첨삭 저장이 마일리지 오류 때문에 실패하면 안 된다.
3. **커밋은 기존 라우트의 커밋에 함께 태운다.** 서비스 함수는 `add`/`flush`까지만 하므로, 기존 `db.session.commit()` 앞에 호출을 넣는다.
4. **`student_id`를 정확히 넘긴다.** 첨삭은 업로더가 강사 계정이므로 `current_user`가 아니라 `Essay.student_id`를 써야 한다. 이 부분을 착각하면 강사에게 점수가 쌓인다.

## 연결 지점

### 1. RW01 리라이팅 — `app/essays/routes.py`

첨삭 확정(finalize) 처리 지점에서 `is_finalized`를 True로 바꾸는 코드 바로 뒤에 적립을 호출한다.

```
award_points(student_id=essay.student_id, activity_code='RW01',
             source_type='essay', source_id=str(essay.essay_id),
             occurred_at=essay.finalized_at)
```

확정을 취소하는 기능이 있다면, 그 지점에서 `cancel_points('essay', essay_id, '첨삭 확정 취소')`를 호출한다.

### 2. QZ01 / QZ02 퀴즈 — 어휘퀴즈·스키마퀴즈 양쪽

퀴즈 세션이 완료되어 `score`가 확정되는 지점에서 호출한다.

- 정답률 60% 이상이면 QZ01
- 100점이면 QZ02를 추가로 한 번 더
- `source_type='quiz_session'`, `source_id`는 세션 ID
- 두 퀴즈 계열의 세션 모델이 다르므로, 공통 헬퍼 함수를 하나 만들어 양쪽에서 호출할 것

정책상 "회차당 1회"인데 회차 컬럼이 없으므로, **세션 ID 기준 1회**로 처리한다. 유니크 제약이 중복을 막는다.

### 3. QS01 질문 등록 — `app/community/routes.py`

게시글 작성 처리에서 `category == 'question'` 이고 작성자가 학생일 때만 적립한다.

- `source_type='post'`, `source_id=str(post.post_id)`
- 상태는 `pending`으로 들어간다 (규칙의 confirm_delay_hours = 24)
- 작성자가 학생이 아니면 적립하지 않는다. `User.role`로 판별하고, 해당 `Student` 레코드를 찾아 `student_id`를 넘긴다

게시글 **삭제** 처리에서 `cancel_points('post', post_id, '게시글 삭제')`를 호출한다.

### 4. CM01 댓글 — `app/community/routes.py`

댓글 작성 처리에서 학생 작성자일 때 적립한다. `source_type='comment'`, 상태는 `pending`.

댓글 삭제는 **실삭제에서 소프트 삭제로 바꾼다.**
- 삭제 처리에서 `db.session.delete()` 대신 `is_deleted=True`, `deleted_at=utcnow()` 설정
- 댓글 목록·개수 조회 쿼리 전부에 `filter(Comment.is_deleted == False)` 추가
- 대댓글이 있는 댓글의 표시 방식은 기존 UX를 유지하되, 삭제된 댓글은 목록에서 제외
- 삭제 시 `cancel_points('comment', comment_id, '댓글 삭제')` 호출

**댓글 조회 지점을 빠짐없이 찾을 것.** 한 곳이라도 놓치면 삭제된 댓글이 화면에 남는다. 수정한 파일과 라인을 보고서에 모두 적을 것.

### 5. EX01 우수답안 / QS02 우수질문 — 관리자·강사 화면

기존에 우수답안을 선정하는 기능이 있으면 그 지점에 연결하고, 없으면 **이번 단계에서는 서비스 함수만 준비하고 화면 연결은 4단계로 미룬다.** 조사 보고서에 따르면 `HallOfFame`은 수동 등록 게시판이므로, 이것과 자동 연동할지는 별도 결정 사항이다. 임의로 연결하지 말 것.

EX01에는 **강사당 주 3명 상한**이 있다. `mileage_service`에 전용 검사 함수를 추가한다.

```python
def can_select_excellent(teacher_id, at=None) -> tuple[bool, int]
    # 월요일~일요일 기준 해당 강사의 EX01 지급 건수를 세어
    # (가능 여부, 남은 횟수) 반환
```

### 6. 취소 처리 공통

정책 제5조에 따라, 근거 활동이 사라지면 포인트도 회수한다. 위에서 언급한 삭제 지점 외에 관리자가 게시글·댓글을 삭제하는 경로가 따로 있으면 그곳도 연결한다.

## 확인 스크립트

`test_mileage_hooks.py`를 작성해 아래를 확인한다.

1. 첨삭을 확정하면 해당 **학생**에게 500점이 붙는가 (강사가 아니라)
2. 같은 첨삭을 다시 확정해도 점수가 늘지 않는가
3. 질문 카테고리 글을 쓰면 pending 100점이 생기는가
4. 그 글을 삭제하면 점수가 사라지는가
5. 댓글을 삭제하면 소프트 삭제되고 화면 조회에서 빠지는가
